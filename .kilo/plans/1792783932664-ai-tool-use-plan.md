# Plan — AI Tool Use / Function Calling for AquaLedger

## Goal
Enable the Persian AI assistant to perform real actions in the app (not just parse transactions) via natural language. User says something like "رئیس ۵۰۰ هزار واریز کرد" or "۲۰ فلتر ۳ مرحله‌ای به انبار اضافه کن" and the AI executes the corresponding store/domain operation.

## Scope (in / out)

### In scope
- New server endpoint `POST /api/ai-tool-call` (Express + Netlify mirror later if needed).
- Tool registry mapping tool name → zod schema → pure handler.
- Confirmation step (two-phase) for money-moving / inventory-mutating actions.
- Frontend orchestrator: send text → receive tool_call → show confirmation if required → execute → show conversational result.
- Initial tool set limited to capabilities that already exist in `src/domain/` and `src/state/` (no new business logic, only wiring).

### Out of scope
- UI route/theme/modal control (navigateToRoute, updateThemeSettings, openModal) — not backed by store state.
- PDF / Excel export, SMS marketing, bank webhook inspection, knowledge base search, client error logs — explicitly deferred in `docs/PLAN.md` known gaps.
- New domain business rules (e.g. stock-in pricing rules beyond incrementing `PartItem.stock`).

## Decisions (final)
1. **Endpoint:** `POST /api/ai-tool-call`, separate from `/api/analyze-transaction`. Existing endpoint unchanged.
2. **Model response:** Gemini returns either an `AIAnalysisResult` (for `/api/analyze-transaction`) OR a `ToolCall` object `{ name, arguments }` for `/api/ai-tool-call`.
3. **Confirmation:** Two-phase. Money/inventory-mutating tools return `pending_confirmation`; frontend shows Persian confirmation; user confirms → second call executes.
4. **Money:** Integer Toman only; Persian/Arabic digits +ワード numbers normalized via `src/lib/persianNumbers.ts`.
5. **Auth/quota:** Same `auth` + `aiRateLimiter` + `checkAiUsage` as `/api/analyze-transaction`.

## New files to create
1. `server/toolRegistry.ts` — registry: `ToolDefinition { name, description, inputSchema (zod), handler, requiresConfirmation }`.
2. `server/aiToolCall.ts` — `/api/ai-tool-call` handler: validate body, run Gemini/tool extraction, execute handler, apply suspicion/finalize if financial, return result.
3. `src/lib/aiTools.ts` (client-side) — tool schemas + orchestrator functions: `callAiTool(text)`, `confirmAndExecute(toolCall)`.
4. `src/components/AiToolOrchestrator.tsx` (or integrate into existing chat UI) — confirmation dialog + result display.

2. `server/gemini.ts` — add `RESPONSE_SCHEMA_TOOL` (zod-validated tool call output) and `analyzeToolCall` function (or reuse `analyzeWithGemini` with new schema).
3. `src/types/schemas.ts` — add `toolCallSchema`, `toolResultSchema` zod schemas.
4. `src/state/transitions.ts` — possibly add `RECEIVE_TOOL_RESULT` action if needed; otherwise reuse existing actions (`RECEIVE_TRANSACTION`, `ADD_CLIENT`, `SAVE_SETTINGS`, `SET_PARTS`, etc.).
5. `src/data/repository.ts` — add `restockPart` / stock-in capability if missing (currently `decrementStock` only; `savePart` exists but no atomic increment).

## Data flow
1. User types/speaks Persian sentence.
2. Frontend calls `/api/ai-tool-call` with `{ text, context }`.
3. Server validates auth + quota, calls Gemini with `RESPONSE_SCHEMA_TOOL`.
4. Gemini returns `{ name, arguments }` (tool call).
5. Server looks up tool in registry. If `requiresConfirmation` → returns `{ status: 'pending_confirmation', toolCall, summary }`.
6. Frontend shows Persian confirmation dialog (e.g. "آیا مایل به تسویه ۲۵۰ هزار تومان بدهی خانم عباسی هستید؟").
7. On user confirm, frontend calls `/api/ai-tool-call` again with `{ toolCall, confirmed: true }`.
8. Server executes handler (store action or domain function), returns `{ status: 'ok', result, conversationalSummary }`.
9. Frontend displays result and re-hydrates store if state changed.

## Failure modes
- Gemini invalid/tool unknown → rule-based fallback parser (if amount present) or Persian error message.
- Insufficient stock → Persian warning (mirrors `planStockDecrement` errors), sale not blocked (per DECISIONS D15).
- Zero / suspicious amount → `finalizeAnalysis` warnings + confidence penalty (existing server logic).
- Offline → enqueue text in `src/data/outbox.ts` (existing pending queue), retry on reconnect.
